# 性能・RAMの測定と制約

[CLIで測定する](CLI.md) · [SDK API](API.md) · [サンプル操作](SAMPLES.md)

## 時間の区分

| 項目 | 測定範囲 |
| --- | --- |
| モデルロード | `prepare` によるロード時間。同じモデルを保持中は0 ms |
| 参照準備 | 参照音声の読込・変換・特徴準備 |
| TTS生成時間 | 音声合成とAudioSeal付与。モデルロード・参照準備・WAV保存を除く |
| TTS RTF | 生成時間÷出力音声長。10秒の音声を2秒で生成すると0.2 |
| 最初のPCM | 最初の音声データが用意されるまで。スピーカーから音が出る時刻とは異なる |
| ASR変換時間 | ファイル読込・16 kHzモノラルPCM16への変換 |
| ASR認識時間・RTF | 認識時間、および無音追加前の入力音声長に対する比率 |

GUIサンプルは全文のWAVが完成してから再生します。アプリの応答時間を測る場合は、入力受付から実際の再生開始までを別に計測します。

## 初回と反復の測定

初回はCore MLのコンパイルやMetalランタイムの初期化を含みます。Core MLでは新しい入力形状の特殊化が反復生成にも影響する場合があります。
ロード済みのengineを再利用し、初回ロード・初回推論・反復推論を分けて測定してください。

比較時は端末・OS・Release構成・モデルrevision・文章・参照音声・caption・seed・文分割・AudioSeal設定を記録します。
実行順、低電力モード、熱状態、他の処理も結果に影響します。複数回の中央値と範囲を確認します。
短文は固定費の比率が大きく、長文と同じRTFにはなりません。

## RAMの読み方

`TASK_VM_INFO.phys_footprint` による**アプリ全体**の値をMiB（1,048,576 bytes）で表示します。
モデル重みだけの専有量や、配布ファイルの容量とは異なります。

現在値は約0.5秒、ロードと推論中はそれぞれ約10 ms間隔で取得します。
最大値はその処理中に観測したサンプルの最大です。サンプル間の短い増加は取り逃す可能性があります。
取得できない値はnil／「—」となり、取得回数・取得エラー数・最大サンプル間隔も確認できます。

TTSの `SynthesisResult.memory`、ASRの `RecognitionResult.memory` は推論中の値です。
ロード中は別の `ProcessMemorySampler` を開始して測ります。[SDKの計測例](GETTING_STARTED.md#ramとロード時間を測る)を参照してください。

方式を切り替えると先のモデルを解放しますが、Core ML・Metal・OSのキャッシュは残る場合があります。
方式単独の値を比較する場合はアプリを再起動します。`release()` はセッションを解放し、ディスク上のモデルとキャッシュは保持します。

## speech.cppのiPhone実測例

測定日2026-10-18。iPhone 17 Pro / iOS 27.0.1、最適化したDiagnostics構成、Metal 4 tensor。
同じアプリ本体・モデルでランタイム0.8.8と0.8.10を比較しました。
実行順は0.8.8→0.8.10→0.8.10→0.8.8。各入力の最初の1回を除き、各プロセス5回、各版10回の中央値です。
ロード・参照準備・音声変換は推論時間に含めません。

TTSはF16、4ステップ、後続デコード窓128、参照なし、seed 12345、AudioSealあり。
ASRは同じReazonSpeech Q4_Kと入力WAVを使用し、beamはCPU、greedyはGPUデコーダーです。
低電力モードはオフ、熱状態は全実行でnominalでした。

| 処理・入力 | 0.8.8 | 0.8.10 |
| --- | ---: | ---: |
| TTS 出力3.68秒・RTF | 0.2089 | 0.2067 |
| TTS 出力9.72秒・RTF | 0.1905 | 0.1939 |
| TTS 出力5.64秒・RTF | 0.2248 | 0.2092 |
| ASR 入力4.40秒・beam | 176.2 ms | 186.9 ms |
| ASR 入力4.40秒・greedy | 101.5 ms | 109.5 ms |
| ASR 入力7.34秒・beam | 225.8 ms | 227.8 ms |
| ASR 入力7.34秒・greedy | 136.7 ms | 132.1 ms |

TTSの短文・長文はおおむね同等でした。3番目の文はプロセス別の中央値が旧版0.2010〜0.2539、新版0.2047〜0.2284と変動しています。
連続生成の入力順で結果が変わるため、この文の集計値だけで高速化したとは判断できません。
ASRの短い入力は新版が約6〜8%遅く、長い入力は約−3〜+1%の範囲でした。

0.8.10のアプリ全体RAMの最大観測値はTTS約2103 MiB、ASR約559 MiB。
旧版はTTS約2093 MiB、ASR約559 MiBでした。
新版の解放後はTTS145〜176 MiB、ASR165〜190 MiBでした。
取得エラーは0、最大サンプル間隔は約13.2 msです。
ロード時間は新版TTSで21.69秒／1.79秒、ASRで490 ms／378 msを観測しました。初回と反復は区別してください。
保持中の同じモデルへの `prepare` はTTS・ASRとも0 msでした。

新旧でASRの認識文字列は一致しました。TTSは3文とも音声長が一致し、各版内では同じseedの反復PCMが一致しました。
新旧のPCMは長文では一致し、ほかの2文では異なりました。
聴感上の優劣、消費電力、ライブマイク入力の性能はこの測定の対象外です。
Core MLとspeech.cppの同条件による性能優劣を示す測定ではありません。

## Core MLの軽量INT8版

現行版とINT8版の数値誤差・認識内容・推定品質・iPhone上のRTFは[音質と速度の測定](QUALITY.md)にあります。
この測定は上のspeech.cpp測定と入力・実行条件が異なります。

## 音声・入力・保存容量

- 本文はBOSを含め256トークン、潜在系列は768フレームまでです。文字数から上限を一律には判定できません。
- サンプルは全文を一度に合成し、上限超過をエラーにします。Core ML SDKの既定の文分割では、対応する長さエラーで再分割します。
- 参照には3〜10秒程度の明瞭な1人の音声を使用します。Voice Designの追従や参照音声との完全な声質一致は保証されません。
- 同じseedでも方式・端末・OS・演算先が異なるとPCMは一致しません。保存WAVで発音・欠落・余分な発話・音の崩れも確認してください。
- SDKはチャンク通知中も完成PCMを保持します。48 kHz mono PCM16は1分あたり約5.76 MBで、モデル・中間テンソル・再生バッファのRAMが別に必要です。
- ディスクにはモデル、取り込みコピー、コンパイルキャッシュ、参照音声・特徴、生成WAVを保存します。[保存と削除](VOICE_REGISTRATION.md)を参照してください。
